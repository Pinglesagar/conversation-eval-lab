Evaluation harness / One finding / n = 1

The grader marked it down for not asking questions.

It asked five.

  • A trainee adviser's call was spoken — every line synthesised to audio, the audio transcribed back, and the transcript graded by the same rubric that grades text.
  • The question detector is body.endswith("?"). The transcript that actually gets graded is the unformatted one, and across the adviser’s eight turns the only punctuation character in it is an apostrophe.
  • So discovery scored 0/4 on a call where 5/8 adviser turns ended in a question mark and 7/8 contained one.
  • 16 turns
  • 181.303625 s
  • Two vendors
  • 0 API keys
  • Discovery 0/4

Where it breaks

The detector wants a ?. The scored transcript has none.

Three versions of the same sentence exist in this pipeline. Only one of them is graded, and it is the one with the punctuation stripped out.

Sent

…hoping to achieve with your investments?

Ends in ?

Display vendor’s formatted transcript

…hoping to achieve with your investments?

Ends in ? but is not graded

Graded unformatted, text_heard

No ? anywhere

Across the eight adviser turns the graded transcript’s only punctuation character is the apostrophe. Over all sixteen it adds exactly one more — the hyphen in brother-in-law. There is no full stop, no comma and no question mark anywhere in it.

Why the graded one is bare The formatted transcript is a second, separately billed request, and its prettifying fabricates a word error rate. So the harness grades the raw channel — which carries no sentence punctuation at all.

The questions really were still there This call carries a second, independent grade of the same unpunctuated transcript: an LLM judge rather than the rule. It scores discovery 4/4 where the rule scores 0/4. So the words were there to be read, and one of the two instruments could not see them. Not a claim that the judge is the better instrument. It moves the opposite way on mandatory_disclosure — 0/4 against the rule’s 4/4, and that rule counts compliance keywords rather than reading the disclosure register, which is a seeded defect of its own. Is the gap just punctuation? Almost — but not entirely

Both sides were normalised by lab.voice.wer.normalise — the same function the word error rate uses, which lowercases, expands contractions, strips punctuation and converts number words to digits. The reference is each turn's spoken_form, which is what was sent to the synthesiser. Each surviving edit is then classified on its own.

  • 16turns
  • 10edits
  • 9orthographic
  • 1content

The one content difference

  • Turn 6, order 11, the customer speaking.
  • Sent “I understand what you’re saying.” → heard “understand what you’re saying”.
  • The recogniser dropped the word I. That is the only genuine content edit on the whole call.

The nine orthographic ones

  • mr → mister ×3
  • timeframe → time frame ×3
  • summarise → summarize ×2
  • per cent → percent ×1

Which is the point: the recogniser did its job. The transcript is faithful. The failure is entirely in what the detector demands of it.

What else it found

Four more instruments that were wrong.

The finding above is a detector that could not see a question. These four are the same shape — the thing doing the measuring was the thing at fault. Three of them are this harness’s own; the fourth is a vendor’s recogniser. Every rate below is recomputed from a committed artefact by the command beside it, unless it is explicitly labelled historical.

Finding / the grader itself

It will not fail anybody.

The rubric scorer agrees with the reviewer on who to pass, and almost never agrees on who to stop.

  • Recall, on sessions a reviewer would fail0.281 (9/32)
  • Specificity0.947 (36/38)

The two rates point opposite ways, and that is the finding: the instrument is not noisy, it is biased toward passing. Quoting either alone inverts the conclusion.

The full confusion matrix, and the refusal
  • Positive class fail. n = 70: TP 9, FP 2, FN 23, TN 36.
  • Precision 0.818 (9/11). Cohen's κ 0.241.
  • It certifies roughly seven in ten of the sessions a competent reviewer would stop.

The gate refused it

  • TPR 0.281 (9/32) is below the required 0.85
  • registry refused the judge in CI mode: JudgeBelowThresholdError

Finding / the judge

A judge whose own gate refused it.

Written for a gate, measured against it, and turned away. The rewrite cleared.

  • v1 recall0.250 (2/8)
  • v2 recall1.000 (8/8)

Both versions score a perfect specificity — 1.000 (16/16). A gate on specificity alone would have passed a judge that missed six real defects in eight.

Thresholds, and how it was decided
  • Thresholds 0.85 true-positive rate and 0.85 true-negative rate, minimum 10 items, scored on point.
  • v1: κ 0.308, refused — TPR 0.250 (2/8) is below the required 0.85.
  • v2: κ 1.000, cleared.
  • 24 items each, model azure/gpt-4.1.
  • Decided by re-running CalibrationReport.meets, not by reading a printed rate.

Wrong before it goes silent.

Finding / the promise detector

A literal is a check that works once.

A detector matching literal strings had full recall against a scripted agent, then went blind against a paraphrasing model. Same defect, both times.

  • Against the scripted agent1.000 (2/2)
  • Against the paraphrasing model historical0.143 (1/7)

Over 30 conversations a generous hand-written detector found 7/30 unbacked confirmations. The literal detector caught 1 of those 7. Four misses were ordinary synonyms; two were not a vocabulary problem at all — the patterns use an ASCII apostrophe and the model types U+2019, so a correct pattern never matched.

The denominators, and what was replaced
  • 2/2 is a floor, not a rate. Two selected rows, one run each, over fixtures/replay_run, against seeded defect BUG-1 — a booking claimed with no committing tool call. The scripted agent says one string every time, so a literal pattern is correct forever.
  • 1/7 is labelled historical. The literal pattern set it measured was replaced by the rewrite and is not in the tree, so the numerator cannot be recomputed. The denominator can be, and is.
  • Denominator warning. The 1/7 is the fixtures/live_run corpus of 30 conversations. A separate 1/6 exists over the six large-party conversations of fixtures/live_full. Two runs, two denominators; they are not the same measurement.
  • Today's detector: 7/7, plus one more the hand-written detector missed. On the 24-item hand-labelled set, recall 1.000 (8/8) and specificity 1.000 (16/16).
  • It decides on a regex over the agent's words plus event-stream position: the first spoken commitment with no create_booking, modify_booking or cancel_booking before it.
